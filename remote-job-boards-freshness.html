Why this matters when you're job hunting

Recruiters post to multiple boards, but the freshness of each board's top page differs wildly. If you only scan one board and it happens to be stale on the day you look, you miss the newest — and most competitive — roles. Two practical takeaways:

1. Check recency, not just volume. A board with 98 listings that are all 3 weeks old is worth less than a board with 120 that were posted this morning. Sort your search by published date.

2. Aggregate, then sort. The robust move is to pull all the boards into one stream and rank by how recent each listing is. That's exactly what the GigWatch API does — one call returns every listing with its published timestamp and source, so you (or your script) can always see which boards are moving right now.

Measure it yourself (no account, no API key)

Pull the full live feed and compute freshness per board in ~10 lines of Python:

import json, urllib.request, datetime
from collections import defaultdict

r = urllib.request.urlopen("https://remote-jobs-api.tten.no/v1/jobs?limit=500")
jobs = json.load(r)["jobs"]
now = datetime.datetime.now(datetime.timezone.utc)

def age_h(j):
    try:
        return (now - datetime.datetime.fromisoformat(j["published"])).total_seconds()/3600
    except Exception:
        return None

t = defaultdict(int); d24 = defaultdict(int)
for j in jobs:
    t[j["source"]] += 1
    a = age_h(j)
    if a is not None and a <= 24:
        d24[j["source"]] += 1

for s in sorted(t, key=lambda x: -t[x]):
    print(f"{s:<10} {t[s]:>4} live  {d24[s]:>4} in 24h  {100*d24[s]/t[s]:.0f}% fresh")

Run it any day and you'll get that day's answer — the board that's freshest now may not be Jobicy tomorrow.
